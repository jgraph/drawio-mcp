# Converting Mermaid, PlantUML and CSV

The app server's `create_diagram` sends a model's Mermaid, PlantUML or draw.io CSV here, and gets back draw.io XML: real cells the user can edit, laid out and styled, or a syntax error that names the line and how to fix it. Without it, the source went to the viewer, which drew it with draw.io's own converters in the browser: the model never saw the cells, a misspelled header gave a blank frame, and nothing told it what was left out. Those converters are draw.io's (drawio-mermaid, drawio-plantuml, the CSV import of the viewer bundle) and run in a browser only, so this module reads the formats itself. The types it doesn't read still go to them (`{fallback: true}`); `mcp-app-server/AGENTS.md`, **Mermaid, PlantUML and CSV converted on the server**, has what the server and the viewer do with the result.

## Rules

- **Headless and deterministic,** as `shared/semantic` (its `AGENTS.md`): no DOM, no timers, the same text gives the same XML, in the Worker, in Node and in the viewer, which runs the same code for its preview (bundled by `mcp-app-server/src/semantic-bundle.js`, so the same module syntax rules apply: single-line named imports, `export` in front of a declaration or `export { a, b };`).
- **Layout and look are `shared/semantic`'s.** A parser turns its format into a semantic description (`{type, title, direction, groups, nodes, edges}`) with `styles: true`: a node's `style` holds the draw.io keys the source asks for (a shape, the colors of a `classDef`, a PlantUML `#color`), and the engine adds them to the calm theme's, the node's keys winning; `width` and `height` give a node a size of its own (a fork bar); a label of spaces is no label (a start dot). Flowcharts and activity diagrams are laid out as flowcharts, ER schemas as ER, CSV trees in tiers (`architecture`), CSV flows as flowcharts. Sequence diagrams have no semantic type: `sequence.js` places them itself, in draw.io's UML shapes (`umlLifeline`, `orthogonalPerimeter` activation bars, `sequenceEdgeStyle` messages, `umlFrame` fragments, `shape=note`), with the calm colors.
- **Errors say where and how.** A syntax error is `{error}` with `syntaxError(format, line, text, problem, fix)`: "Mermaid syntax error on line 3 (`subgraph X`): the subgraph "X" has no `end`. Fix: close every subgraph with a line `end`." The line is the line of the text the model sent (frontmatter and comments counted).
- **Draw what can be drawn.** Anything that has a place in the diagram but can't be shown as written is drawn as near as possible and named in `warnings` (a shape drawn as a box, a subgraph's own direction, a click action, a PlantUML `skinparam`, a CSV placeholder that names no column), so the model learns it without a failed call. Only what leaves the diagram unclear is an error (an unclosed block, an arrow without its other end, a CSV row with an open quote, a `connect` naming a column the header doesn't have).
- **Partial text** (`options.partial`, the viewer's preview while the model writes): what is still open at the end (a subgraph, an entity, a PlantUML group, a CSV quote) is closed there instead of being an error.

## Files

| File | Purpose |
|------|---------|

| `common.js` | `syntaxError`, labels as plain text (`plainLabel`: `<br>`, Markdown, entities), CSS-like declarations as draw.io keys (`cssToStyle`, `cssColor`, CSS color names in hex) |

## Mermaid

Flowcharts (`flowchart`, `graph`, `flowchart-elk`): every node shape of the classic syntax and of `@{ shape: … }` that draw.io has (others as a box, with a warning), subgraphs as frames (nested, with titles, members by id), edge kinds (`-->`, `---`, `-.->`, `==>`, `<-->`, `--o`, `--x`, lengths), labels in both syntaxes, chains (`A --> B & C --> D`), `classDef`, `class`, `:::`, `style`, `linkStyle` and the frontmatter title. ER: entities with their attributes (`PK`, `FK`, `UK`, comments), the crow's-foot relations between them as draw.io's ER arrows, the relation's label on its line. Sequence: participants and actors (with aliases, `create`, `destroy`, `box`), every arrow, activations (`+`/`-` and `activate`), `autonumber`, notes, the fragments `alt`/`else`, `opt`, `loop`, `par`/`and`, `critical`/`option`, `break` and `rect`. A Mermaid theme or `init` config is not used, with a warning: the calm theme stays, with the colors of `classDef` and `style`.

## PlantUML

The block from `@start…` to `@end…` (several diagrams: the first), `'` and `/' '/` comments. Sequence: every participant kind with `as`, `#color`, `<<stereotype>>` and `order`, `box`, `autonumber` (start, step, `stop`, `resume`), `activate`/`deactivate`/`destroy`/`create` and the `++`, `--`, `**`, `!!` shorthands, `return`, notes (left, right, over, across, `hnote`/`rnote`, over several lines), `ref over`, dividers (`== … ==`), delays (`...`), spaces (`||n||`), the groups `alt`/`else`, `opt`, `loop`, `par`, `break`, `critical`, `group`, and every arrow (heads, `--` dashed, `[#color,dashed,bold]`, messages from and to the diagram's edge with `[` and `]`). Activity (the new syntax): actions over several lines, `start`, `stop`, `end`, `kill`, `detach`, arrows with labels and colors, `if`/`elseif`/`else`, `switch`/`case`, `while`, `repeat`/`backward`, `fork`/`fork again`/`end fork`/`end merge`, `split`, lanes (`|#color|Name|`), `partition`s and notes. `skinparam`, `<style>`, themes and the preprocessor are left out with a warning, as is a line the converter doesn't know. Class, use case, component, state, timing, the old activity syntax and the other families (`@startmindmap`, `@startgantt`, …) go to the viewer.

## CSV

As draw.io's import reads it: the `#` lines first (a value continued on the next `#` line with `\`, `##` a comment, `-` or nothing the default), then the header and the rows. Each row is a shape that keeps its columns as data (`<UserObject … placeholders="1">`, the label template with `%column%` placeholders, as draw.io writes it), less the `ignore`d columns and with the `link` column as its link; `style` with its placeholders filled in (a key left empty, `fillColor=` for an empty column, is dropped, so the calm color stays), or `styles` by `stylename`, `labels` by `labelname`; `identity` and `namespace` for the ids (`0` and `1`, the page's own, get an `n`), `parent` for frames (with `parentstyle`'s colors), `connect` for the lines (several targets in one value, `invert`, `label`, `sourcelabel`/`targetlabel`, `fromlabel`/`tolabel`, `style`, a shape for an unknown target with `unknownStyle`), `width` and `height` (a number, `@column`, `auto`; the image `label` shape gets room for its picture). Layouts: `auto` (a tree or anything connected in tiers, rows without lines stacked as draw.io stacks them), `verticaltree`, `horizontaltree`, `orgchart` (in tiers), `verticalflow`, `horizontalflow` (flowcharts), `organic` and the ELK ones (in tiers, with a warning), `none` (each row at its `left` and `top`). `list`, `container`, `circle` and a custom layout go to the viewer.
